# TASK-023 — Parse Splash pastes against ContestRules

## Goal

Text copied from a Splash contest page becomes one row per game with both teams, the home spread and the kickoff. Teams with a known alias are matched, and the rest come back as unmatched instead of guessed. A contest's rules are validated against a typed model with Splash as the preset.

## Context

- Task list: `docs/08-tasklist.md` › M2 › M2.8 (a risk spike, moved forward from Phase 4). Sized M rather than the stub's S: with the rules model, the parser, its tests and fixture, and the pydantic dependency, it touches more than 3 files, all in the engine.
- Product: `docs/01-product.md` › Observable outcomes › F-03 (the Week 6 paste gives "9 rows match · 1 unmatched", "Hou Texans" @ "Jax").
- Architecture: `docs/02-architecture.md` › Risks & mitigations (Splash paste format: test against a real page copy; unmatched rows fall back to a picker); › Testing strategy › Levels › Unit: engine (the parser on `design/sample-splash-10062026.txt` (then named `sample-splash.txt`) and on the Week 6 paste; `ContestRules` validation).
- Data model: `docs/03-data-model.md` › Contest lines (paste, per-platform parser, match through `team_aliases`, flag unmatched rows); › Your data (`ContestRules` fields and the Splash preset; push = `zero (confirm)`).
- Decisions: D-038 (paste, not scraping), D-036 (team matching through aliases), D-022 (no sport-specific code in shared modules).
- Inputs:
  - `design/sample-splash-10062026.txt`: a real page copy, added 2026-10-06 (Oct 1–5, 2026: CFB and NFL, final and preview games, rank lines such as `#3ranked #3`, records, scores, totals, a `Picks lock:` time).
  - The Week 6 paste generated by `blocks` in `design/handoff/designs/contest-data.js`, in the same shape as the real page. It's written out once as a text fixture under `python/engine/tests/fixtures/`; `design/` is protected and stays untouched.
  - `design/sample-splash-10152026.txt`: the owner's fresh copy, added 2026-10-15 (Oct 13–19, 73 game blocks). It's a full-page copy, so unlike the older file it has no `PTS` header but does have a `Picks made` / `/4` picks counter, and some NFL records include ties (`3-1-1`).
- Rules: CLAUDE.md › Domain conventions (`spread_home` is negative when home is favored).
- **Decide at the plan gate:** where `ContestRules` lives (sport- and platform-agnostic, light core with pydantic; `engine/core/` doesn't exist until M3.1) and where the Splash parser lives (per platform); which time zone the page's kickoff times are in (none is printed); how lines like `PK` or a missing line are represented; the shape of the alias lookup the parser takes (no database here).

## Acceptance criteria

- [ ] AC-1: Given `design/sample-splash-10062026.txt`, the parser returns one row per game block, as many rows as the file has `Over ` lines. Each row has the away and home names as written and `spread_home` equal to the home side's line, with the away line equal to −`spread_home`. Rank lines, records, scores, statuses and totals never appear in a team name.
- [ ] AC-2: Given the Week 6 paste fixture and an alias lookup holding every name in it except "Hou Texans" and "Jax", the parser returns 10 rows: 9 matched to team IDs and 1 unmatched row carrying the raw names "Hou Texans" and "Jax". Texas @ Oklahoma has `spread_home` +7, and UNLV @ Boise State has −10.
- [ ] AC-3: Given a game block whose two side lines don't sum to zero, or that has no line, the parser returns that row with a problem reason (`lines disagree`, `no line`) and no spread, and still returns every other row.
- [ ] AC-4: `ContestRules` accepts the Splash preset (period `week`, sports `[cfb, nfl]`, slate `curated`, exactly 4 picks, lock `per_game_kickoff`, scoring `point_per_win`, push `zero`). Given `picks_per_period` 0 or an unknown scoring value, it raises a validation error naming the field.
- [ ] AC-5: Given `design/sample-splash-10152026.txt`, the parser returns 73 rows (one per `Over ` line), with none lost or duplicated; the `Picks made` / `/4` counter and tied records (`3-1-1`) never appear in a team name.

## Out of scope

- Matching a parsed row to a `games` row by teams and date (the contest import, M6).
- Other platforms' parsers and manual entry.
- Settling Splash's push rule (an open question in `docs/decisions.md`; the preset records `zero` as 03 does).
